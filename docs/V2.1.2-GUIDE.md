# V2.1.2: usability and semester management

Your Acer now contains real university records. **Complete the backup and verification steps before pulling this release.** Run the commands individually in Command Prompt, not PowerShell, and stop if any step fails. These commands assume `C:\Projects\student-dashboard` and the existing scheduled task named `Student Dashboard`.

## A. Backup before update

1. While the application is still running, open **Settings → Semesters & data maintenance → Backups & data export → Export JSON backup**. Save this fresh export in your Downloads folder as `student-dashboard-before-v2.1.2.json`. If that name already exists, retain the old export elsewhere and ensure this path refers to the new export, not an earlier download.
2. Disable automatic startup and gracefully stop the dashboard:

```bat
cd /d "C:\Projects\student-dashboard"
schtasks /Change /TN "Student Dashboard" /Disable
node scripts/windows/dashboard.mjs stop
node scripts/windows/dashboard.mjs status
```

Continue only when the launcher reports Stopped and port 3000 is free. Disabling the task alone does not stop the application. Close other browser clients for maintenance.

3. Create a dated full backup outside the repository. Keep this Command Prompt open: later commands use its `SD_BACKUP` variable. The timestamp prevents overwriting an earlier backup. `%I` below is for an interactive Command Prompt, not a batch file.

```bat
for /f %I in ('powershell -NoProfile -Command "Get-Date -Format yyyy-MM-dd-HHmmss"') do set "SD_BACKUP=C:\StudentDashboardBackups\%I-before-v2.1.2"
mkdir "%SD_BACKUP%"
copy /B "%USERPROFILE%\Downloads\student-dashboard-before-v2.1.2.json" "%SD_BACKUP%\portable.json"
robocopy "data" "%SD_BACKUP%\data" /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XJ
copy /B ".env" "%SD_BACKUP%\.env"
echo %SD_BACKUP%
npm run db:backup
```

For example, the folder might be `C:\StudentDashboardBackups\2026-09-08-153000-before-v2.1.2`. Write down the **actual folder printed**. Robocopy exit codes 0–7 are successful/non-fatal; 8 or higher means failure. Check its summary has zero failed files. `copy` must report one file copied for each file. The `data` copy includes `student.db`, any SQLite sidecars and other local runtime files. The extra `npm run db:backup` JSON is saved in `C:\Projects\student-dashboard\backups`; it does not replace the external backup. Keep these files private because the full copy contains authentication and push credentials.

Confirm the counts match the records you expect, the files have non-zero sizes and the extra local JSON has today's timestamp. Verify every copied data file and `.env` against the stopped originals without printing their contents:

```bat
powershell -NoProfile -Command "$ErrorActionPreference='Stop'; $src=Join-Path (Get-Location) 'data'; Get-ChildItem -LiteralPath $src -File -Recurse | ForEach-Object { $dest=Join-Path ($env:SD_BACKUP+'\data') $_.FullName.Substring($src.Length+1); if ((Get-FileHash -LiteralPath $_.FullName).Hash -ne (Get-FileHash -LiteralPath $dest).Hash) { throw 'Data copy mismatch' } }; if ((Get-FileHash -LiteralPath '.env').Hash -ne (Get-FileHash -LiteralPath ($env:SD_BACKUP+'\.env')).Hash) { throw 'Environment copy mismatch' }; Write-Output 'Full backup verified'"
```

Do not pull if verification fails. A parse/count check is not a restore rehearsal; retain both JSON and the complete stopped database copy.

## D. Recovery if records are missing

First check semester selection and filters. If a restore is needed, stop using the app on other devices and keep the scheduled task disabled. Restoring JSON **replaces academic/productivity records with the backup snapshot**, rather than merging them. Later edits will be replaced. The current data is backed up first and restore runs in a transaction. Existing passwords and sessions are not replaced by JSON.

### Restore through Settings when the app works

1. Keep the task disabled and run the dashboard manually using `node scripts/windows/dashboard.mjs start` from `C:\Projects\student-dashboard` if it is stopped. Do not start a second copy.
2. Sign in at `http://localhost:3000`.
3. Open **Settings → Semesters & data maintenance → Backups & data export → Restore a backup → Choose JSON backup**.
4. Select `portable.json` inside the **actual dated external backup folder** printed in step A, for example `C:\StudentDashboardBackups\2026-09-08-153000-before-v2.1.2\portable.json`.
5. Confirm replacement, wait for “Backup restored” and reload every open client. Verify records with All semesters and appropriate filters.
6. Only after verification, stop the manual app and enable/run the scheduled task using the commands in section C. The pre-restore JSON copy is in `C:\Projects\student-dashboard\backups`.

### Restore JSON through CLI

In a new Command Prompt, set `SD_BACKUP` to the actual backup folder you wrote down (replace the example timestamp). Do not continue while the app or port 3000 is active:

```bat
cd /d "C:\Projects\student-dashboard"
set "SD_BACKUP=C:\StudentDashboardBackups\2026-09-08-153000-before-v2.1.2"
schtasks /Change /TN "Student Dashboard" /Disable
node scripts/windows/dashboard.mjs stop
node scripts/windows/dashboard.mjs status
dir /a "%SD_BACKUP%\portable.json"
npm run db:backup -- "%SD_BACKUP%\portable.json" --confirm
node scripts/windows/dashboard.mjs start
```

Wait for “Backup restored. Previous data saved in backups/.” before starting. Verify records in the browser, then stop and enable/run the task as in section C. The CLI uses the same validation, transaction and automatic pre-restore backup as Settings. If the database is damaged so that JSON restore cannot read/back up its current contents, use the full-copy recovery below.

## E. Recovery if the database or application is damaged

Use this only with a verified full backup. It restores the entire database, credentials and local runtime state at the backup time. Keep the old damaged files for investigation; do not merge an old `student.db` with newer SQLite WAL/SHM files.

1. Stop the dashboard and verify port 3000 is free:

```bat
cd /d "C:\Projects\student-dashboard"
schtasks /Change /TN "Student Dashboard" /Disable
node scripts/windows/dashboard.mjs stop
node scripts/windows/dashboard.mjs status
```

If the launcher cannot confirm a safe stop/free port, do not copy a database over a running process. Resolve that failure first.

2. Select the actual full backup folder, check it exists and create a separate dated holding folder for the current state:

```bat
set "SD_BACKUP=C:\StudentDashboardBackups\2026-09-08-153000-before-v2.1.2"
dir /a "%SD_BACKUP%\data\student.db"
dir /a "%SD_BACKUP%\.env"
for /f %I in ('powershell -NoProfile -Command "Get-Date -Format yyyy-MM-dd-HHmmss"') do set "SD_HOLD=C:\StudentDashboardBackups\%I-before-recovery"
mkdir "%SD_HOLD%"
if exist "data" move "data" "%SD_HOLD%\data"
if exist ".env" move ".env" "%SD_HOLD%\.env"
```

Continue only if the old `data` directory and `.env` were moved successfully (or did not exist). The target `C:\Projects\student-dashboard\data` must not exist before the copy below. This avoids mixing database generations.

3. Restore the complete directory and environment file:

```bat
robocopy "%SD_BACKUP%\data" "data" /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XJ
copy /B "%SD_BACKUP%\.env" ".env"
dir /a "data\student.db"
dir /a ".env"
```

Check zero failed files in the Robocopy summary and one environment file copied. Re-run the hash verification command from section B: it now compares the restored files against the backup. Do not touch `backups`, and do not run seed/reset/destructive Prisma commands.

4. Repair installed dependencies/build if needed, then validate and start:

```bat
npm install
npm test
npm run typecheck
npm run build
node --import tsx --test tests/startup-production.integration.ts
node scripts/windows/dashboard.mjs start
```

Sign in with the password valid at the full-backup time and verify your records. Use a second terminal for status/logs. Only then stop the manual app and enable/run the scheduled task as in section C. Keep `SD_HOLD` and the original backup until recovery is confirmed. No source downgrade is required for this release because the database schema is unchanged.

## Behaviour and implementation

- `lib/format.ts` uses explicit `Intl.DateTimeFormat('en-AU', ...)` for `DD/MM/YYYY` and `h:mm AM/PM`, including midnight/noon. Civil ISO strings are formatted in UTC as wall-clock components to avoid browser-timezone shifts. Real timestamps use the configured application timezone. Dates remain ISO in SQLite, JSON backups and native input values. Contextual calendar month/day headings and chart ticks remain compact; full dates are given where a date is displayed, in input hints and accessible date labels.
- `DateTimeInput` retains safe native date/time pickers and adds an accessible Australian formatted hint. Native picker appearance is controlled by the browser/OS. No ambiguous `DD/MM/YYYY` string is parsed into storage.
- Ordinary text inputs request `autoComplete="off"`; records and preferences still persist normally. Login keeps `current-password`/`new-password` so password managers still work. Browsers/extensions may choose to ignore autocomplete hints; existing browser history is not erased.
- Teaching weeks retain seven-day blocks anchored to the semester's first teaching date. A whole block covered by one or more Break records is skipped; overlapping breaks count once. Partial breaks pause classes on the specified dates while retaining that teaching block. The display shows before-start, teaching week, break with resume date/week and teaching-complete states. The configured teaching-week total caps the count. The existing percentage is still calendar semester elapsed, labelled separately.
- Semester breaks use existing `ImportantDate` records with `kind: 'Break'`, a semester ID, inclusive start/end dates and the existing revision-protected CRUD. Manage them under Settings → Semesters or when editing an existing semester. Global Break records from Calendar also apply. No migration is needed.
- Recurring classes are suppressed during breaks and resume afterwards without altering class series. Calendar/timetable show the break on each included date. Tasks, assignments, exams and manual study sessions remain. Deleting a break requires confirmation and restores recurring-class visibility; it does not delete class series or deadlines.
- Dashboard Edit Mode has a page-level editing state, a primary Done button, grouped movement controls, expandable Size settings and separated Hide. Existing layout persistence, drag/resize, keyboard alternatives and device-specific layouts remain.
- The global timer is a compact floating card near the lower-right, above phone navigation with safe-area clearance. There is no full-width background strip. Scroll space at the end of the page keeps the last controls reachable. End calls the existing `timer.finish` action, stops elapsed-time accumulation and opens Study review. Save/discard, duplicate-save protection and visible-client sync are unchanged.
