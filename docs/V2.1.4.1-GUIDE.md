# V2.1.4.1 — Semester progress and floating timer polish

UI-only patch. No database migration, dependency, timer persistence/sync, authentication, backup-format or infrastructure change is included.

## Changes

Semester progress uses `Semester name | DD/MM/YYYY · Week N/M`, preserving `|` after the name. The shared Analytics summary uses the same formatter and teaching-week calculation, including special semester states and resumption information.

The floating timer exists only while Running or Paused. Its old Ready to save/Review & save code is removed. End retains the existing finish action and opens Study review; other devices hide the floating surface as soon as their synchronised snapshot reaches review. Save/Discard, editable actual minutes, quick note and duplicate-session protection are preserved. Internal cleanup remains available only through review discard in the UI.

A dedicated grip allows touch dragging on phone/tablet, snaps to one of four corners and stores only the corner name in browser localStorage (`student-timer-corner`). Resize/visual-viewport listeners and measured safe-area/header/navigation bounds keep placement valid after rotation and keyboard changes. No coordinates or academic data are stored. Opening/closing the onscreen keyboard never overwrites the selected corner. Mouse desktops retain their existing placement.

## Safe Acer update

Use **Command Prompt**, not PowerShell, and run each command individually. Stop on any failed step. These commands assume the existing folder `C:\Projects\student-dashboard` and scheduled task `Student Dashboard`.

Before stopping, export a fresh JSON backup from **Settings → Semesters & data maintenance → Backups & data export** and retain the downloaded file. Finish/save any active study session if practical. Close other clients during maintenance.

```bat
cd /d "C:\Projects\student-dashboard"
schtasks /Change /TN "Student Dashboard" /Disable
node scripts/windows/dashboard.mjs stop
node scripts/windows/dashboard.mjs status
```

Continue only when the dashboard is stopped and port 3000 is free. Disabling the task does not stop an already-running app. Create a dated backup outside the repository, retaining credentials and sessions along with the database. Keep this Command Prompt open and record the printed folder path.

```bat
for /f %I in ('powershell -NoProfile -Command "Get-Date -Format yyyy-MM-dd-HHmmss"') do set "SD_BACKUP=C:\StudentDashboardBackups\%I-before-v2.1.4.1"
mkdir "%SD_BACKUP%"
robocopy "data" "%SD_BACKUP%\data" /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XJ
copy /B ".env" "%SD_BACKUP%\.env"
npm run db:backup
echo %SD_BACKUP%
```

`%I` is for an interactive Command Prompt. Robocopy must report zero failed files (exit codes 8 and above mean failure). Verify the stopped database and `.env` copies without printing their contents:

```bat
powershell -NoProfile -Command "$ErrorActionPreference='Stop'; $src=Join-Path (Get-Location) 'data'; Get-ChildItem -LiteralPath $src -File -Recurse | ForEach-Object { $dest=Join-Path ($env:SD_BACKUP+'\data') $_.FullName.Substring($src.Length+1); if ((Get-FileHash -LiteralPath $_.FullName).Hash -ne (Get-FileHash -LiteralPath $dest).Hash) { throw 'Data copy mismatch' } }; if ((Get-FileHash -LiteralPath '.env').Hash -ne (Get-FileHash -LiteralPath ($env:SD_BACKUP+'\.env')).Hash) { throw 'Environment copy mismatch' }; if ((Get-Item -LiteralPath ($env:SD_BACKUP+'\data\student.db')).Length -eq 0) { throw 'Empty database backup' }; Write-Output 'Full backup verified'"
```

Keep both the JSON export and the full backup. For recovery, the existing [JSON and full database recovery instructions](V2.1.3-GUIDE.md#d-recovery-if-records-are-missing) still apply; use your actual V2.1.4.1 backup path and exported JSON filename. Do not restore data as part of a normal update.

`npm install` retains the existing safe checked-in migration check; V2.1.4.1 adds no migration. Nothing seeds or resets data. `npm run build` includes production CSS verification. Verify localhost, LAN and your existing private Tailscale HTTPS address. Reload all browser/PWA clients. Check existing subjects, tasks, To-dos, assessments and study history. Clear filters/select All semesters if a record appears missing.

After the checks below pass, stop the manual launcher and resume the existing task:


Wait for Ready in the logs. For later maintenance, disable the task and gracefully stop with the same commands above. No Task Scheduler trigger, Tailscale Serve or Run unattended configuration change is needed.

## Device checks after updating

- Reload browser/PWA clients. Semester progress should show `Semester name | DD/MM/YYYY · Week N/M`, with the existing break/resumption, before-start and teaching-complete wording where appropriate.
- Start one session on your Acer. On your phone/iPad, drag using the small grip above the timer title. A movement of 8 CSS pixels begins a drag; release snaps to the closest safe corner. Tap the grip to cycle corners, or focus it and use arrow keys. Pause/Resume/End remain separate clickable buttons.
- Try all four corners on phone, iPad portrait and iPad landscape. Bottom phone corners should clear navigation. Rotate the device, open an input keyboard and scroll the visible viewport. The selected corner should remain on screen. In exceptionally short viewports the card can scroll internally to reach controls.
- Choose a corner, reload and start another session later: the corner should be remembered for this browser/origin. Localhost, LAN and Tailscale addresses have separate browser storage. If storage is blocked, the in-memory choice works and new loads fall back to bottom-right. Desktop with a mouse and a wide viewport keeps the existing fixed position; touch-capable devices and viewports at most 800px get the handle.
- Pause on one device and resume from another. End from the floating timer: the initiating device should open Study review and the floating timer should disappear on both devices. End stops time but does not save a StudySession. Check actual minutes editing and quick note, then Save once and verify one session. End a second test session and Discard: no new session should appear. The grip must not trigger Pause or End while dragging.
- Reboot if you wish to verify the existing automatic startup. Physical Windows, iPad, phone, keyboard and reboot checks must be performed locally.

## Automated coverage and limits

Tests cover all four corners, persisted/corrupt/unavailable storage, phone/iPad portrait/landscape bounds, rotation-equivalent corner placement, keyboard/panned viewport bounds, drag threshold, extra-finger rejection, clamping, snapping and arrow-key choice. Rendering tests cover Running/Paused visibility and complete removal in review/saved/discarded states, separate drag/action buttons, and preservation of the main review form.

The authenticated two-client timer test verifies End reaches both clients in review, both hide the floating timer, accumulation stops and no session is automatically saved. Existing tests verify save-once and discard-without-saving. Production CSS verification covers the drag handle, safe-area probe and constrained scrolling card alongside existing guards.

Live responsive browser/touch verification was unavailable in the execution environment; simulated geometry and rendering tests are not a physical-device test. Use the checks above on your Acer, iPad and phone.
