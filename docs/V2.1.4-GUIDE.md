# V2.1.4 — timer, sidebar and Dashboard progress cleanup

This release changes UI only. No database migration, new dependency or backup-format change is required. SQLite records, authentication, timer persistence/synchronisation, reminders, Web Push, To-dos, recurring tasks, Windows startup, Task Scheduler and Tailscale are unchanged.

## Changes

- Active floating, Study, Dashboard timer and Focus Mode views have no Cancel timer action or cancellation confirmation. Pause/Resume and End retain their existing server actions and cross-device updates. The main view now labels Finish as End. Existing countdown round/break controls remain available when relevant.
- End enters session review. The floating timer links to the review page; the main timer shows the review form. Review offers Save session and Discard session. V2.1.3 exposed only Save on that form; Discard now uses the existing internal `timer.cancel` cleanup action, which creates no StudySession. It is available only after End, not as an active timer control. Duplicate-save protection remains unchanged.
- Removed the floating Cancel helper, confirmation handlers, cancellation CSS and obsolete confirmation test. Internal cleanup and its backend/synchronisation tests remain used by review discard.
- The navigation scroll container retains `overflow-y: auto`. `scrollbar-width: none` hides Firefox/modern Chromium scrollbars; `::-webkit-scrollbar` hides the WebKit/Chromium track and thumb. Links, focus behaviour and the saved collapse toggle are unchanged. No JavaScript scrollbar is added.
- Dashboard starts directly with its heading. The existing Semester progress widget displays one bold summary: `QUT Y1S2 | 11/10/2026 - Week 11/13` (general format: `Semester name | DD/MM/YYYY - Week N/M`). The existing civil date formatter and teaching-week calculation are reused. The shared summary in Analytics also uses this format.
- Break state uses `Semester name | DD/MM/YYYY - Semester Break` and retains the teaching-week resumption line. Before teaching starts and after teaching ends, the date is followed by the existing start countdown or Teaching complete label. No invalid week number or duplicate normal teaching-week label is shown.

## Safe Acer update

Use **Command Prompt**, not PowerShell, and run each command individually. Stop on any failed step. These commands assume the existing folder `C:\Projects\student-dashboard` and scheduled task `Student Dashboard`.

Before stopping, export a fresh JSON backup from **Settings → Semesters & data maintenance → Backups & data export** and retain the downloaded file. Finish/save any active study session if practical. Close other clients during maintenance.

```bat
cd /d "C:\Projects\student-dashboard"
schtasks /Change /TN "Student Dashboard" /Disable
node scripts/windows/dashboard.mjs stop
node scripts/windows/dashboard.mjs status
```

Continue only when the dashboard is stopped and port 3000 is free. Disabling the task does not stop an already-running app. Create a dated backup outside the repository, retaining credentials and sessions along with the database. Keep this Command Prompt open and record the printed folder path.

```bat
for /f %I in ('powershell -NoProfile -Command "Get-Date -Format yyyy-MM-dd-HHmmss"') do set "SD_BACKUP=C:\StudentDashboardBackups\%I-before-v2.1.4"
mkdir "%SD_BACKUP%"
robocopy "data" "%SD_BACKUP%\data" /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XJ
copy /B ".env" "%SD_BACKUP%\.env"
npm run db:backup
echo %SD_BACKUP%
```

`%I` is for an interactive Command Prompt. Robocopy must report zero failed files (exit codes 8 and above mean failure). Verify the stopped database and `.env` copies without printing their contents:

```bat
powershell -NoProfile -Command "$ErrorActionPreference='Stop'; $src=Join-Path (Get-Location) 'data'; Get-ChildItem -LiteralPath $src -File -Recurse | ForEach-Object { $dest=Join-Path ($env:SD_BACKUP+'\data') $_.FullName.Substring($src.Length+1); if ((Get-FileHash -LiteralPath $_.FullName).Hash -ne (Get-FileHash -LiteralPath $dest).Hash) { throw 'Data copy mismatch' } }; if ((Get-FileHash -LiteralPath '.env').Hash -ne (Get-FileHash -LiteralPath ($env:SD_BACKUP+'\.env')).Hash) { throw 'Environment copy mismatch' }; if ((Get-Item -LiteralPath ($env:SD_BACKUP+'\data\student.db')).Length -eq 0) { throw 'Empty database backup' }; Write-Output 'Full backup verified'"
```

Keep both the JSON export and the full backup. For recovery, the existing [JSON and full database recovery instructions](V2.1.3-GUIDE.md#d-recovery-if-records-are-missing) still apply; use your actual V2.1.4 backup path and exported JSON filename. Do not restore data as part of a normal update.

After backup verification:

```bat
git pull --ff-only
npm install
npm test
npm run typecheck
npm run build
node --import tsx --test tests/startup-production.integration.ts
node scripts/windows/dashboard.mjs start
```

`npm install` retains the existing safe checked-in migration check; V2.1.4 adds no migration. Nothing seeds or resets data. `npm run build` includes production CSS verification. Tests use disposable databases; the lifecycle tests need port 3000 free. The final start command stays running in this window. In a second Command Prompt:

```bat
cd /d "C:\Projects\student-dashboard"
node scripts/windows/dashboard.mjs status
node scripts/windows/dashboard.mjs logs
```

Verify localhost, LAN and your existing private Tailscale HTTPS address. Reload all browser/PWA clients. Check existing subjects, tasks, To-dos, assessments and study history. Clear filters/select All semesters if a record appears missing.

After the checks below pass, stop the manual launcher and resume the existing task:

```bat
node scripts/windows/dashboard.mjs stop
schtasks /Change /TN "Student Dashboard" /Enable
schtasks /Run /TN "Student Dashboard"
node scripts/windows/dashboard.mjs status
```

Wait for Ready in the logs. For later maintenance, disable the task and gracefully stop with the same commands above. No Task Scheduler trigger, Tailscale Serve or Run unattended configuration change is needed.

## Device checks after updating

- On a shorter laptop screen, scroll the expanded sidebar with the wheel/trackpad; reach Settings and every navigation item. Tab through the links and verify focus remains visible. Collapse, navigate and expand; the sidebar must remain usable with no visible track/thumb.
- Check iPad portrait and landscape, and phone navigation/touch scrolling. Check that the floating timer fits without horizontal page overflow and that Pause/Resume and End are reachable.
- Start one test session. Pause on one device, observe the other, then resume from the second. End and confirm both devices enter review. Save once, verify exactly one StudySession, and confirm the timer clears on the other device. For a second test session, End then Discard session; no new StudySession should appear.
- Confirm Dashboard has no date/week line above its heading. Enable Semester progress through Edit Dashboard if your saved layout hides it. Verify one bold date/week summary, wrapping naturally on narrow screens. Existing Semester Break, before-start and teaching-complete states should retain their correct wording; do not edit real semester dates just to test these states.
- A reboot check may confirm the existing automatic startup still works. Physical Windows, iPad, phone and reboot testing must be performed locally.
