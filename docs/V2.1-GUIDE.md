# V2.1 usability polish

This release changes the app UI and timer synchronisation. No schema migration, dependency or secret is added. SQLite, password authentication, backups/restore, reminders, Web Push, PWA access, the Windows launcher/readiness budget, Task Scheduler and Tailscale retain their existing architecture. No Spotify integration is included.

## Navigation and full screen

- Desktop has expanded navigation and a 76px icon rail. Use Collapse navigation / Expand navigation. Labels remain accessible, hover titles identify icons and the current page retains its filled highlight.
- The choice is saved per browser and origin, like theme. Different devices and localhost/LAN/Tailscale addresses can have different choices. Tablet-sized windows default to the rail when there is no saved choice. Clearing browser storage resets this preference; records are unaffected.
- Above 800px the sidebar can collapse; at 800px or narrower it uses the existing drawer. Phone navigation below 768px retains Today, Tasks, Add, Calendar and More, with distinct light/dark surfaces, a filled active state and iPhone safe-area space.
- Enter Full Screen is in the app header. It hides navigation and secondary chrome independently of the timer's Focus Mode. It requests the standard Fullscreen API only from your click. If unavailable or refused, the distraction-free app layout still works, including iPad Home Screen apps. It never enters automatically or saves fullscreen across reloads.
- Exit Full Screen is always visible. Escape exits the app layout; a browser fullscreen-exit event also restores it. Browser controls remain the fallback for exiting browser-level fullscreen.
- The timer dock occupies its own space below the scrolling page, above phone navigation. Time is prominent; title and running/paused state are separate. On small screens the controls form a second row. Focus Mode remains separate.

## Timer synchronisation

Each visible signed-in page holds one authenticated, uncached GET to `/api/timer`. The response contains only the active timer, its revision cursor and server time. If nothing changed, Next.js holds the request for up to 25 seconds without repeatedly querying SQLite. This is a long poll, not a 25-second delay after a change.

A successful timer transition commits to SQLite, then wakes the waiting requests through an owner-scoped event in the existing Node process. Start, Pause, Resume, Finish, Cancel and Save therefore normally appear on another visible connected device within **1–2 seconds**, including a remote Start when that device previously had no timer. The client then opens its next held request. Countdown ticks stay timestamp-based and do not write to SQLite.

There is no guaranteed maximum over a disconnected/suspended device or slow network. A request has a 30-second client timeout; failures retry after 1, 2, 4, 8 then at most 15 seconds and show a reconnecting message. Hidden pages cancel their request and reconnect immediately on visibility/focus. The 25-second server refresh also recovers from missed in-process signals; it does not replay old transitions. Server restart recovers the current timer from SQLite.

Old responses from cancelled connections are ignored. The dedicated timer state cannot be overwritten by an older general snapshot. Existing revision checks reject stale actions; duplicate-save and single-active-timer protections remain. Session authentication is checked before opening a request and again before releasing a held response. There are no CORS/origin/authentication exceptions.

When shutdown begins, the timer connection releases its held read requests immediately. Next.js still owns graceful draining and process exit; the existing launcher retains its 60-second stop wait without a forced kill. Wait for its stopped/free-port confirmation before updating.

## Recurring-series deletion

Recurring series are separate cards with frequency, subject, status and outstanding/next date. Add/Edit opens a spaced form with Save and Cancel. It stays visually separate from the ordinary Tasks filters.

Delete series requires confirmation and removes the recurrence definition in one transaction, preventing future generation. It removes an outstanding future task only if it is untouched: Not Started, revision zero, no recorded hours, completion timestamp, notes or linked timer.

Completed, overdue, edited, started and timer-linked tasks remain as normal Tasks. Their recurrence-link rows are removed when the definition is deleted; task contents, completed history and recorded StudySessions remain. You can delete a retained task separately using the normal task controls if you no longer want it. Stale or foreign-owner series deletion is rejected.

## Removed automatic planning

Removed the DayPlanner component, Plan My Day button/date picker/proposals/empty messages, Plan Next Week launcher, `suggestDay` generator, unused proposal styles and `plan.save` API action. Weekly Review calculations now live in `lib/weekly-review.ts`. Today, classes, due/overdue tasks, ranked recommendations, workload/capacity information, Weekly Review and normal manual study-session creation remain. Previously saved sessions are ordinary StudySession rows and are retained. No database migration is needed.

## Update on the Acer

Run each command individually in Command Prompt. Stop on failures. Export a JSON backup from Settings first.

```bat
cd /d "C:\Projects\student-dashboard"
schtasks /Change /TN "Student Dashboard" /Disable
node scripts/windows/dashboard.mjs stop
```

Continue only after the launcher confirms Stopped and port 3000 is free. Privately copy the full `data` directory and `.env` outside the repository while stopped, preserving VAPID keys, database sidecars, passwords and sessions. Then:

```bat
npm run db:backup
git pull --ff-only
npm install
npm test
npm run typecheck
npm run build
node --import tsx --test tests/startup-production.integration.ts
node scripts/windows/dashboard.mjs start
```

Tests use disposable databases. Port 3000 must be free for lifecycle tests. The readiness tests take roughly two minutes; the production test also verifies graceful stop with a waiting client. No build runs automatically at boot.

Leave the start terminal open. In a second Command Prompt:

```bat
cd /d "C:\Projects\student-dashboard"
node scripts/windows/dashboard.mjs status
node scripts/windows/dashboard.mjs logs
```

Check localhost, LAN and your existing Tailscale HTTPS address. Reload/reopen each browser/PWA once after updating to load the V2.1 client. No new push permissions or keys are needed. After the manual checks:

```bat
node scripts/windows/dashboard.mjs stop
schtasks /Change /TN "Student Dashboard" /Enable
schtasks /Run /TN "Student Dashboard"
```

Keep your existing At startup task, Node executable path, Tailscale Run unattended and Serve configuration. Future maintenance begins with disabling the task and gracefully stopping the application; disabling alone does not stop the running process.

## Physical acceptance checks

- Laptop: collapse/expand, reload and confirm the choice persists. Check the active-page highlight and icon titles. Enter/exit fullscreen through the button, Escape and browser exit.
- iPad: landscape rail, portrait rail/drawer, Home Screen distraction-free mode, visible exit, keyboard and touch access to recurring-form Save/Cancel. Check light/dark and both densities.
- Phone: bottom navigation contrast, active indicator, safe-area clearance and stacked timer controls. Scroll to the last form field and confirm controls remain reachable with the keyboard open.
- With two visible devices, start a stopwatch, pause/resume/finish/cancel from the other device and confirm updates normally arrive within 1–2 seconds. Repeat with a countdown and remote Start from no timer. Briefly disconnect/reconnect one device; confirm it recovers without overwriting the newer state.
- Save a finished session once and confirm no duplicate study hours. Test deletion using a disposable recurring series with a completed historical task and an untouched future task; history stays and future generation stops.
- Check Today, manual study scheduling, Weekly Review, notifications and an existing push subscription. Reboot the Acer and verify private mobile-data access plus launcher status/logs. This must be physically checked on your devices; automated Windows CI is not a physical reboot test.
