# V2.1.1 UI corrections

This is a UI correction release. SQLite schema/data, password authentication, timer persistence and synchronisation, reminders, Web Push, backups, the Windows launcher, Task Scheduler and Tailscale are unchanged. No dependency or Spotify integration is added.

## Collapse investigation and build correction

The existing click handler changed React state and saved the preference. With the matching production stylesheet, browser checks measured the sidebar changing from 236px to 76px and the content margin changing to 76px. The exact Acer failure was not reproduced on its hardware.

A separate concrete defect was reproduced during this release: an incremental `next build` succeeded but emitted the previous stylesheet after CSS edits. Building without its saved cache emitted the current CSS. Stale CSS can leave a newer toggle without its corresponding layout rules, or leave newer timer markup without spacing. This is consistent with the reported symptoms, but does not prove what was loaded on the Acer.

The production build now sets `experimental.turbopackFileSystemCacheForBuild: false`. Each update compiles the current sources. A `postbuild` integration test rejects output missing the current rail, timer, recurrence and task-section rules, or retaining removed fullscreen styles. It runs automatically with `npm run build`, including CI. Boot does not build anything.

The workspace and visual regression harness now share `useSidebarPreference`; the harness no longer has a competing toggle implementation. Functional state updates handle consecutive clicks, blocked browser storage still allows toggling, and the saved preference is loaded before it is written. A fresh phone does not default to the desktop rail. Above 800px the rail is 76px; smaller screens retain the existing drawer/bottom navigation. Preferences remain per browser and origin.

The old visual harness appended raw CSS to compiled CSS, which could mask stale build output. That overlay is removed: the harness uses only emitted production CSS.

## Visible changes

- Application fullscreen entry/exit buttons, icons, hook, Fullscreen API calls, event handling and distraction-free styles are removed. Study Focus Mode and browser/PWA standalone behaviour remain.
- The timer dock separates the activity title, a small status badge, elapsed/remaining label, dominant tabular clock and equal-height Pause/Resume and Finish controls. Narrow displays use two rows. Phone controls stay in the dock above bottom navigation, with safe-area padding and separately scrolling page content. Timer actions and sync are unchanged.
- Recurring tasks is an always-visible section with concise helper copy and a “Your recurring series” heading. Empty state copy and Add recurring task have intentional spacing.
- Each series card separates its task name, schedule, subject, next/outstanding occurrence, status and actions. Delete is a secondary destructive action separated from Edit and retains its confirmation and history-preserving behaviour.
- Add/Edit uses a distinct panel with two columns on wide screens and one column at 800px or narrower. Generate future occurrences and Save/Cancel have separate rows and borders. Ordinary Tasks filters begin in their own section after a substantial break.

## Update on the Acer

Export a JSON backup from Settings first. Run commands individually in Command Prompt and stop if any command fails.

```bat
cd /d "C:\Projects\student-dashboard"
schtasks /Change /TN "Student Dashboard" /Disable
node scripts/windows/dashboard.mjs stop
```

Continue only when the launcher confirms Stopped and port 3000 is free. While stopped, privately copy the complete `data` directory and `.env` outside the repository. Then:

```bat
npm run db:backup
git pull --ff-only
npm install
npm test
npm run typecheck
npm run build
node --import tsx --test tests/startup-production.integration.ts
node scripts/windows/dashboard.mjs start
```

No cache-deletion command is needed: the corrected build configuration avoids the saved build cache. Do not remove `data`, `.env` or `backups`. The tests use disposable databases; the readiness tests take roughly two minutes. Production lifecycle tests require port 3000 to be free.

Leave the start terminal open. In a second Command Prompt:

```bat
cd /d "C:\Projects\student-dashboard"
node scripts/windows/dashboard.mjs status
node scripts/windows/dashboard.mjs logs
```

Check `http://localhost:3000`, your LAN address and your existing private Tailscale HTTPS address. Reload each browser/PWA after the update to load the new client. No new permissions, push keys or Tailscale setup are required.

After manual checks, return to scheduled operation:

```bat
node scripts/windows/dashboard.mjs stop
schtasks /Change /TN "Student Dashboard" /Enable
schtasks /Run /TN "Student Dashboard"
```

For later maintenance, disable the task and gracefully stop the app again. Disabling a scheduled task alone does not stop the running app. Keep the existing At startup trigger, Tailscale Run unattended and Serve background configuration.

## Device acceptance checklist

1. Laptop/desktop and iPad landscape: click Collapse and confirm the sidebar visibly shrinks and content gains width. Navigate to another page and reload; it stays collapsed. Click Expand and reload; it stays expanded. Check active-page highlight, hover titles and keyboard access to the toggle. Check each origin separately because preferences are local to that origin.
2. Header: no fullscreen button or unused gap. Study Focus Mode still opens/exits, and PWA standalone access still works.
3. Timer: test countdown and stopwatch, Running and Paused, light/dark and Comfortable/Compact. Title and status must remain separate, time prominent and actions aligned. Check phone safe areas, bottom navigation and the last page control with the keyboard open. Check iPad portrait and landscape without horizontal overflow.
4. Tasks: check empty recurring section, populated cards, Add and Edit. Verify the single-column phone editor, field gaps, Generate checkbox, Save/Cancel footer and separate ordinary task filter section. Use a disposable series for Delete; confirm completed history stays.
5. Two devices: Start/Pause/Resume/Finish still synchronise, and saving a finished session does not duplicate hours. Verify normal tasks, notifications and your existing push subscription.
6. Reboot the Acer and check launcher status/logs and your private Tailscale URL over mobile data. Physical Windows/device/reboot checks must be performed locally.

## Regression checks for maintainers

`npm test` covers rendered navigation accessibility, timer state/mode markup, fullscreen removal, recurring-series create/edit/delete and the existing timer synchronisation tests. `npm run build` also runs `tests/production-css.integration.ts` on the actual emitted stylesheet. Run the unchanged Windows production lifecycle test after building.

For local browser QA, build first, then run `node scripts/visual-fixture.mjs`. The generated `public/v2-fixture.html` and `public/v2-sizes.html` contain fictional data and the real components/controller, without an authentication bypass or mocked production API. “Run navigation checks” executes `tests/sidebar-browser.ts`: actual DOM clicks verify rail/content widths, navigation, active icon, expand and saved choices. Check refresh persistence separately. The fixture adds running/paused/review, countdown/stopwatch, empty, density and theme controls. Do not submit fixture forms to a real app; business actions are covered against disposable databases by the test suite. Remove the generated fixture assets after QA and before the final production build.
